# Yui · v0.2 第一步

当前发行版本 **0.2.0-alpha.8**：手机内部换用用户新提供的银白星星素材，银色顶栏、星点背景、银白接收气泡与淡粉发送气泡、银色列表和输入按钮。昵称回到顶栏正中，保留返回与「⋯」设置；保持无尾气泡、头像与气泡底边对齐、时间位于头像下方。沿用原有4S外壳、美化和「信息／通讯录／我」导航。

供图裁片在构建时内嵌，保留原有透明边缘；示例人像、文字和状态不会作为用户资料或真实业务展示。返回、更多、人物资料和演示输入仍由真实控件操作。语音、表情、转账、拍照、相册、通话和更多工具仍是待接入占位。联系人实际会话保持空状态，不调用AI或保存真实消息。

这仍是v0.2第一小步的外观更新，完整v0.2、正文原位消息与手机同源记录、真实续聊均未完成。真实ST／TT安装与移动软键盘仍待验证。


## 更新、安装与禁用

仓库：[yui-ovo/yui-pocket](https://github.com/yui-ovo/yui-pocket)。已安装时在酒馆扩展管理中更新 **Yui**，然后刷新页面。首次安装：酒馆 → 扩展 → 安装扩展 → 粘贴仓库链接 → 刷新。扩展不依赖酒馆助手。

若之前使用助手脚本，请先停用旧 Yui / ruru 脚本，不要同时启用两种入口。禁用或卸载在扩展管理中完成，并按宿主提示刷新；支持官方生命周期钩子的宿主会立即清理自身节点和监听，没有这些钩子的分支需刷新。

备用助手 JSON：构建生成 `dist/yui.v0.2-step1.json`，交付副本 `outputs/yui.v0.2-step1.json`。在 Tavern Helper / JS-Slash-Runner **脚本库**导入后，启用“Yui · v0.2 第一步 · 通讯录”。沿用已核实的助手 4.9.5 格式，默认禁用。JSON 可解析及模拟运行通过，不代表真实宿主导入已验证。旧版本 JSON 仅保留历史，不用于本次升级。

## 通讯录怎么用

主屏只保留 **信息、美化**，移除独立联系人图标。打开信息后，底部有 **信息／通讯录／我** 三个页签。通讯录负责人物资料，“我”中打开“我的名片”；页签在三个首页显示，聊天及编辑页使用返回按钮。Home 回主屏，× 关闭。

1. 先在酒馆打开有效聊天，再进入 **信息 → 通讯录**。没有聊天或宿主接口不可用时只提示，不保存到通用默认档。
2. 右上角 **＋** → **从当前角色卡带入** 或 **手动创建人物**。带入只填表，不自动加好友。原卡标题可以改成真正的人物名字，不修改原卡；同一来源卡可以录入多个独立人物。群聊没有单一来源卡时可手动创建。
3. 填写人物名字、手机备注、可选简短设定、虚构账号和开局关系，点击保存。备注为空显示名字；备注用于列表和会话标题，资料页仍可查看人物名、来源与稳定 ID。
4. **已经是好友**进入好友列表；**认识但未加好友**可单独选择是否知道账号；**尚不认识**只在“人物设置 · 仅玩家可见”中登记。资料编辑是玩家操作，不表示剧情里的 user 已知道这些信息。
5. **我 → 我的名片**填写或生成本存档 user 的虚构账号，保存后固定。人物账号也固定保存；本存档内不区分大小写检查重复。账号为3–40位字母、数字、下划线或短横线；不提供真实通讯服务。
6. 信息页显示好友的空会话。顶部为“‹ 信息 / 联系人备注或名字 / ⋯”。点击名字可进入资料；点“⋯”进入聊天设置，其中包含联系人资料和聊天外观。隐藏消息头像不会隐藏更多按钮。新联系人没有历史消息，输入/发送明确禁用，提示聊天尚未接入。

信息和通讯录提供当前页的名字/备注筛选；不请求网络、不按账号发现陌生人。未加好友的人只出现在通讯录的玩家设置区，不因筛选而混入信息页。筛选词仅在当前面板内保留，切换剧情存档清空。

聊天采用淡粉纸纹标题、浅色立体尾巴气泡、两侧头像和头像下的时间。新安装/恢复阅读默认使用圆形消息头像，已有头像圆角设置沿用。底部工具条可横向滑动，含 **转账、拍照、相册、通话**；输入栏有拍照、相册、更多位置，均明确标注“待接入”，点击只显示占位提示，不打开相机、上传图片、拨号或转账。向上箭头是发送：仅独立演示可用，真实联系人继续禁用。

“小桃”放在信息页独立标注的 **独立演示 · 不属于本存档** 入口中。它保留三个虚构示例，发送只增加本次内存气泡，不回复、不保存；不会被自动录入好友，也不会复制给新人物。资料/阅读页往返不会销毁整个手机，演示草稿保留；关闭清空草稿，刷新/禁用清空演示消息。

## 头像与资料默认

- 来源卡人物默认使用其来源文件的宿主头像；手动人物没有来源头像，显示文字占位，不借用主角头像。
- **上传头像**接受本地 PNG/JPEG/WebP，复用既有图片校验：上限2MB、尺寸不超过4096×4096、最长边缩至512、重新编码。头像保持比例并居中裁切；ST 模式图片只存浏览器；TT 模式随联系人保存到 TT 原生本机资料存储。不会上传 GitHub 或第三方服务。
- **头像图片 URL**仅接受用户明确输入、不带用户名密码的 HTTP(S) 地址；点“加载此头像 URL”才请求。图片站点会收到请求，使用 no-referrer。加载失败保留原头像；已保存外链失效时回退文字占位并在资料预览提示，不持续重试。
- **恢复默认头像**恢复来源卡头像/文字占位。**恢复联系人默认**仅清空备注和恢复默认头像，不改人物名字、ID、账号、关系；点保存才保留。

## 资料保存和隔离边界

以下本机账号键说明适用于普通 SillyTavern。TT 使用下面单列的原生资料存储；两种入口共用源码并自动选择宿主，不会自动合并两种后端的旧资料。

使用官方 `SillyTavern.getContext()` 读取聊天标识、当前卡文件名/群组ID和可用的 `chatMetadata.integrity`；只通过同源 `GET /api/users/me`确认宿主账号，不接触密钥。`saveMetadata()` 会连同完整聊天保存，所以本轮不调用此接口、不读取或写入真实消息，也不改角色卡、世界书、宿主预设。

- 通讯录在本浏览器、本酒馆地址的专用键 `yui-pocket.contacts.v1:<宿主账号>` 中保存。内部以来源文件/群组、聊天文件定位、可用完整性标识映射到独立通讯录 UUID。人物另有永久 UUID，名字、备注、数组下标都不作身份。
- 同卡不同聊天、不同卡、不同宿主账号互相隔离。官方聊天重命名事件会迁移定位关联，通讯录和人物 UUID 保持；错误会提示并停止覆盖。已有数据版本不支持或损坏时停止写入。
- 复制/新分支采用独立空通讯录，本步不自动继承原档资料，因此不共享可变数据。原档与分支分别编辑；历史回退、合并、事件失效尚未实现。
- 本机保存同步写入后读回校验；失败显示提示。保存前重新核实账号和存档，并检查修订版本；关闭/切档取消旧操作。并发窗口可能提示重新读取，跨窗口完全事务锁未实现。
- **不会跨设备、浏览器或酒馆地址自动同步，也不随酒馆聊天导出而备份。** 清理浏览器站点数据会丢失这些资料。关闭/禁用扩展不清除已保存资料。
- 扩展停用期间、外部文件操作引起的重命名/移动，或角色头像文件改名，暂不保证自动迁移。重新创建同名聊天且宿主无完整性标识时无法可靠区分，需目标宿主验证；不要把此步当成完整存档回退方案。

## TauriTavern（TT）适配

适配依据为 [Darkatse/TauriTavern](https://github.com/Darkatse/TauriTavern) 2.2.0 源码，固定 commit 9693a4ec47cd4552f90878bccab453f176de0f18。尚未在真实 TT 安装或真机上验收；同版本号不同构建也可能有接口差异。

- 安装/更新方式相同：TT 扩展管理中使用本仓库，更新 Yui 后重新加载。无需另装 Yui 专用助手脚本。
- 等待 TT 官方 ready Promise 后挂载；禁用期间就绪不会复活旧实例。订阅 api.layout 的安全区域和宿主报告的键盘遮挡，取消订阅时清理。没有该布局 API 时使用原来的 VisualViewport。
- 通讯录通过 api.chat.open(ref).store 保存到 TT 当前数据目录内独立的 yui-pocket 命名空间；不请求 /api/users/me、不假设默认账号、不读写消息或 metadata。卡文件身份采用官方 .png 文件名主体；群聊使用聊天文件 ID。未选择聊天、接口不全或原生存储失败时明确报错，不降级到共用默认档。
- TT 角色资料目录按 integrity 划分。Yui 再用聊天文件名 SHA-256 构成条目键，避免复制档保留相同 integrity 时串资料；复制/新分支仍为空通讯录。启用期间的角色聊天重命名通过原生 renameKey 迁移本扩展条目；目标有资料时不覆盖。
- 保存前校验存档及修订，写入后读回确认，支持原生 JSON 字段重新排序。关闭或切档后，尚未发出的写入取消；**已经发出的原生写入无法撤销，会在原聊天句柄上完成**，不会写到新聊天或复活旧页面。若保存确认失败，返回列表重读后再操作。
- 阅读与机身美化仍使用各自本机键。TT 的通讯录不在浏览器联系人键中，不能只靠清理站点数据清除它；备份、跨设备迁移及宿主删除/复制原生资料的行为未验证，不承诺随聊天导出。
- 仍待真机验证：Android/iOS 软键盘（TT 当前 focus 路由使用 event.target，对 Shadow DOM 输入识别可能不全；仅收到有效 layout 快照时调整键盘空间）、安全区、原生头像/选图、扩展更新钩子、群聊及群聊重命名、应用数据目录切换。旧 TT 若不提供 chat.open/store 接口需升级；本补丁没有调用私有原生桥或修改 TT 源码来绕过限制。

## 阅读与美化分别管理

进入聊天 → **⋯ → 聊天外观**。联系人首页移除阅读设置按钮，聊天设置包含“联系人资料”（头像、人物名字、备注及完整资料入口）和“聊天外观”。完整资料页顶部头像为72px，点击可选择本地图片。

| 设置 | 作用范围 |
| --- | --- |
| 显示消息头像 | 仅控制消息两侧的头像；隐藏时一起收起占位 |
| 消息头像大小 | 24–64px，不改变列表头像、资料头像或导航栏 |
| 消息头像圆角 | 0–50%，方形到圆形，不改变气泡圆角 |
| 气泡文字大小 | 12–24px，只调整消息内容 |
| 气泡文字行距 | 1.2–2.4倍，只调整消息内容 |

对方头像在左、自己的头像在右；预览为明确标注的两条虚构消息，与独立小桃演示共用消息视图组件。预览对方图片取自当前联系人，失败回退占位；自己的名片头像尚未接入，明确用“我”占位，不借用对方图片。真实联系人仍无消息，不把预览写入历史。

实时预览，**保存聊天外观**才写入本机 `yui-pocket.reading.v2`。可选“当前联系人”或“所有联系人”；当前联系人样式按宿主账号、通讯录UUID、人物UUID关联，修改备注不改变身份。保存“所有联系人”会统一默认值并清除已有单独样式，界面明确提示。独立演示只有“所有联系人”选项。

**取消**或离开会撤销未保存的预览。**恢复聊天外观默认**和**跟随所有联系人样式**也先预览，保存后保留；不删除头像、备注、贴纸或挂绳。切换剧情存档时退出旧外观编辑，旧设置页不能再保存。

首次读取会沿用旧 `yui-pocket.reading.v1` 的数值，把原顶部头像选项改用于消息头像；只有明确保存才创建v2记录，旧键不被覆盖。聊天外观始终是当前浏览器/TT WebView的本机偏好，包括单独样式；不会自动跨设备同步，也不随TT原生通讯录备份。

美化保留36枚供图贴纸、原光环与挂绳和本地导入。四角贴纸大小10–100%、旋转±25°、左右/上下各±40px；挂绳大小60–120%、旋转±45°。左挂点正角度、右挂点负角度向外。窄屏大角度可能越过视口边缘，可配合缩小。

美化只写 `yui-pocket.appearance.v1`；恢复默认只清除此键。阅读与机身美化是本浏览器同地址的 Yui 整体偏好，区别于按宿主账号和聊天保存的人物资料。

## 构建与检查

需要 Node.js 22+。无运行时 npm 依赖；现有三个开发依赖仍为 TypeScript、esbuild、Playwright。

```sh
npm ci
npm test
npm run deliver
```

`npm run build` 同时生成根目录 `extension.js` 和备用 JSON。源码、样式与预置图片全部内嵌，无远程 import/CDN运行依赖。仅头像与本源身份核实有本轮授权的网络请求。

Windows 使用已安装 Chrome 运行测试：

```powershell
$env:RURU_BROWSER_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
npm test
```

`npm run preview` 仅启动127.0.0.1:4173的虚构模拟页，不是正式产品网站。正式交付仍在酒馆运行。`tests/profile-mock.js`模拟官方上下文与事件；测试明确禁止读取宿主消息和调用聊天/设置保存或生成接口。测试覆盖卡片带入、独立身份、三种关系、账号重复、资料存储与迁移、头像成功/失败、异步取消、小屏阅读以及原外壳、美化、导航和生命周期。

最新实际结果见 PROGRESS.md，平台证据见 SOURCES.md。真实 SillyTavern / TauriTavern 的安装更新、宿主账号接口、事件时序、存储配额、文件选择、软键盘与主题组合仍需验证。模拟通过不等于真机兼容通过。

## 工程与后续

`host.ts`负责挂载/生命周期；`profile-host.ts`集中宿主资料读取、账号确认、通讯录存储与重命名关联；`contacts.ts`定义资料与校验；`directory.ts`/`profile-editor.ts`提供内屏界面；`reading.ts`管理全局与当前联系人聊天外观；`message-view.ts`为演示和样式预览共用的消息布局，`chat-controls.ts`共用聊天工具占位与输入栏。`appearance.ts`/`beautify.ts`保留美化职责；`demo.ts`仍是独立临时演示集合。

后续世界书候选、账号搜索、双向好友申请、正文结构化关系事件、模型固定账号与接受/拒绝结果感知只写入 ROADMAP。正文原位消息气泡与手机记录的同源数据仍是核心；本轮未实现这些内容，不使用假回复、假申请或自动通过充当完成。
